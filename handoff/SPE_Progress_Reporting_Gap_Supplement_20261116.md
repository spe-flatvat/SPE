# SPE｜実成果と本来の到達点の差分報告・限定補完

**日付:** 2026-11-16  
**Status:** OWNER-DIRECTED / OPERATIONAL SUPPLEMENT / NON-CANONICAL  
**対象:** SPE実務の進捗報告  
**位置づけ:** 2026-11-16付「実装・計算・比較の一括実行方針レシート」「損税マクロ接続最優先・実行方針更新レシート」の不足点のみを補完する。新たな承認ゲート・レビュー・管理工程は設けない。

## 1. 補完する問題

F損税モデルの独立実装、StatusQuo暫定モデル化、F／StatusQuo比較レポートには実成果がある。一方、損税診断からマクロ年次計算への接続は未完了であり、損税解消がGDP・税収・財政指標へ与える影響は未算定である。

本来望ましかった依存関係は、(1) 損税独立実装 → (2) マクロ接続 → (3) StatusQuoモデル化 → (4) 接続済みFとStatusQuoの比較であった。実際には(2)が後回しとなり、接続前の比較レポートが先行した。独立実装完了時点でマクロ接続の未達が十分に伝わらず、Ownerが接続済みと認識してレポートを依頼したことも遅延要因となった。

これは既存成果を無価値とするものではなく、成果の範囲と最終目的までの未達を区別するための整理である。

## 2. 実務報告で必ず区別する3点

進捗を報告するときは、長い管理文書を増やさず、回答本文の中で次を簡潔に明示する。

1. **前回から何が変わり、何ができるようになったか。** 新規機能、計算対象、実行結果、比較可能性を具体的に述べる。
2. **本来の到達点に対して何が未達か。** 独立計算とマクロ接続、比較モデル完成と政策効果の算定、再現性PASSと新しい計算能力を混同しない。
3. **次に必要な実成果は何か。** 未達を埋める実装・計算・比較・引渡しを示す。これを新しい事前工程や承認依頼に変換しない。

既存出力との一致は「再現性の確認」と表現する。開発の進歩を主張する場合は、以前できなかった何が可能になったかを明示する。変化がない場合は、その旨を率直に報告する。

## 3. F損税接続における報告上の境界

- **損税独立実装済み:** 医療・教育・住宅賃貸の損税診断を独立して年次計算できる。
- **マクロ接続未完了:** 診断結果がFマクロのGDP・税収・財政関連指標へ反映される状態には至っていない。効果は「未算定」であり、「ゼロ」とは異なる。
- **StatusQuo暫定モデル・比較レポート出力済み:** 接続前のF／StatusQuo比較として利用できるが、損税マクロ接続後の政策効果比較を代替しない。
- **次の実成果:** 損税接続の実装・2026〜2055年の年次実行・接続ON／OFF差分・必要な検証・成果引渡しを一括で完了する。接続後の計算結果をグラフで確認する場合は、既存のClaude可視化成果を再利用できる。グラフ作成を接続前の別工程にしない。

## 4. 適用境界

本補完は報告の正確性を高めるものであり、追加のレシート、採番、レビュー、承認、進捗台帳を要求しない。既存のOwner承認条件、RP-023／M19–25 HOLD、RP-024 PENDINGは維持する。GitHubの`main`への書込み権限を付与しない。

**結論:** 「完了した作業」と「本来の到達点に対する未達」を同時に報告し、成果の誤認による作業順序の逆転を防ぐ。報告の改善を、実装の代替成果にしない。
